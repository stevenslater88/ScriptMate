# RCA — Redeploy failed at build_image (EAS OTA `eas-update` lane)

**Deployment:** scriptmate-8
**Failed run:** e10f2727-4764-4140-832d-22f55cc0e922 (redeploy, agentic)
**Failed step:** build_image → Cloud Build step #7 "eas-update" (exit 1). Docker backend lane succeeded; only the EAS OTA lane failed, so nothing was promoted — the previous run (966d882b) is still live.

## Symptom (from Cloud Build log tail)
```
Step #7 - "eas-update": [4/4] Building fresh packages...
Step #7 - "eas-update": $ patch-package
Step #7 - "eas-update": /bin/sh: 1: patch-package: not found
Step #7 - "eas-update": error Command failed with exit code 127.
[RETRY] All 3 attempts failed
```
The `yarn install` in the eas-update lane runs the frontend's `postinstall` script (`"postinstall": "patch-package"`), but the `patch-package` binary is not present in `node_modules/.bin`, so it exits 127.

## Root cause
`frontend/package.json` declares `patch-package` (and `postinstall-postinstall`) under **`devDependencies`**, but the deployer's eas-update lane installs with **`NODE_ENV=production`**, which makes yarn v1 skip `devDependencies`. The `postinstall` hook still runs and calls `patch-package`, which was never installed → "not found" (exit 127). The repo has a real patch that this hook is meant to apply: `frontend/patches/expo-camera+17.0.10.patch`.

This is the patch-package README's documented caveat: if `yarn install --production` (or `NODE_ENV=production`) is used, `patch-package` must live in `dependencies`.

## Reproduction (eph sandbox, isolated)
- devDependency + `NODE_ENV=production yarn install` → `patch-package: not found`, **exit 127**, `.bin/patch-package` ABSENT — exact match to the build log.
- Same package with `patch-package` + `postinstall-postinstall` moved to **`dependencies`** → postinstall runs `patch-package 8.0.1 Applying patches...`, **exit 0**, `.bin/patch-package` PRESENT.

## Fix (source — E1 to apply in the preview repo)
In `frontend/package.json`, move these two entries out of `devDependencies` and into `dependencies` (keep the same versions):
```json
"patch-package": "8.0.1",
"postinstall-postinstall": "2.1.0"
```
Leave `"postinstall": "patch-package"` as-is. Run `yarn install` locally so `yarn.lock` updates, then re-trigger the redeploy. After this, the eas-update lane's production install will include `patch-package`, the `expo-camera` patch applies, and step #7 passes.
